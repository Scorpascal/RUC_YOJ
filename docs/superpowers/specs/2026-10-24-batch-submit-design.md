# 纯网页批量提交

用户已确认：最多选择 10 题，一次确认后间隔 3 秒依次发起提交，结果仍到 YOJ 查看。无需扩展、代理或后台登录服务。

## Safari 修订（用户已批准）

- 共享响应窗口在待确认/待响应时可能被下一次导航覆盖；改为每题原生 POST 到独立响应标签，最多 10 个。不预开或重新获取跨站窗口，不依赖窗口引用推断受理。
- 自动预检，清单页的“检测弹窗并开始”按钮就是唯一站内确认，不再弹出第二层确认框或逐题询问。先用两个不含题目数据的空白窗口检测首次和3秒后弹窗能力；不通过时整批不发送，也不记录题目尝试。允许本站弹窗可能需要用户一次浏览器设置；HTTP 安全提示不能绕过，也不能保证只出现一次。
- 不读跨站响应，不声称能够检测弹窗是否真的打开或 YOJ 是否受理。“已请求发起”只指原生表单调用，后续仍至少间隔 3 秒；用户可停止尚未发起部分，状态不明不重发。
- Safari 真实验收发现专用填空接口不兼容当前原生表单；完整 PUBLIC_READY 组装程序经普通入口实测 Accepted。单填空题保留原片段及后台模板复核，纯网页入口只使用发布清单中完整源码哈希与组装哈希一致的程序。目录和快捷清单双向绑定，发送前片段及完整程序都校验；缺证据即阻断，不自动回退到未知载荷。单题页保留复制片段，并展示实际待发送完整程序。
- 表单留在发起文档直到离开，响应页互不覆盖；无凭据、代理或扩展。真实 Safari 验证并核对原站新增记录通过之前不推送修复。

## Approaches

- 采用：沿用原生跨站表单，每题独立结果页。无需安装；只能记录浏览器请求发起，不能读取跨站登录态、是否受理或 Accepted。
- 放弃：复用一个结果窗口，可能覆盖仍待确认/响应的请求，且 Safari 跨站窗口引用不可靠。
- 未采用：YOJ 浏览器助手，可读取逐题响应，但需要额外安装和权限；用户已选择纯网页方案。

## 范围和约束

- 主页支持跨分页/筛选选择，最多 10 题；独立批量页显示题号、语言、提交形态和原站链接，确认之前不发送评测。
- 只接受公开清单中与目录 PUBLIC_READY、已复验状态一致的题目；源码以 SHA-256 核对，预加载全部通过才允许开始。
- 普通题使用 pid/language/code；单填空的纯网页入口使用已核验完整组装程序的 pid/language/code，后台原有 pno/compiler/codes 模板复核不变。保留题目 eno 链接；不推测或绕过原站课程/考试权限。
- 固定间隔 3 秒、独立响应页串行发起。可停止未发起部分；本地异常即停止，已发起请求不可撤销，网页不能可靠检测跨站响应页关闭。
- 用 URL 中的随机编号与有序选题绑定一个批次，sessionStorage 按批次保存选题和已尝试题号。刷新不自动发送；用户可确认仅继续本批次未尝试部分。主页重新选题或明确新建批次可再次选择旧题，并显示此前尝试提醒；旧版按题号全局拦截的记录仅作提醒，不再禁用新批次。发送前持久化尝试，同一批次绝不自动重复不确定请求；不自动过期后重试。不存代码、账号、密码或 Cookie。
- 明示“已请求发起”不等于“原站受理/Accepted”；浏览器仍可能要求用户确认 HTTPS 到 HTTP 的提交。
- 普通题单题提交保持原有行为；单填空单题页采用上述已核验完整程序兼容入口。原 AC、发布证据、脱敏及定时更新流程保留。

## 验收

自动测试覆盖 0/10/11 题、重复/未知/未发布题、来源和哈希失败、两种表单、eno、3 秒节流、重复启动、检测中与发送中停止、存储失败、同批次恢复和新批次重复选题。Safari 用无评测的本机接口验证拦截时零发送、允许后连续响应；浏览器回归区分真实策略与明确标注的 API 边界模拟，避免把自动化默认允许弹窗视为 Safari 的证据。验证桌面/移动及深浅色布局，不向真实 YOJ 重复发出已通过题目的评测。完整回归及暂存树脱敏/一致性检查后，以 Scorpascal 身份推送 main 并核对同 SHA 的 Pages。
