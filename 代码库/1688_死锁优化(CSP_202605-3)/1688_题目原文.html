    #1688. 死锁优化（CSP 202605-3）

    内存限制：256MiB 时间限制：1000 ms 标准输入输出
    题目类型：传统 评测方式：文本比较
    上传者： 20210129
    提交记录 讨论

    题目描述

    死锁优化（deadlock）

    时间 1 秒，空间 512 MiB。

    题目描述

    有 n 个进程与 m 种资源，编号分别为 1～n、1～m。系统按第 1、2、3……段依次运行，每段严格分为申请部分（段首）、处理部分（段中）、释放部分（段末）。资源初始均为待使用状态，每种资源同时至多被一个进程占有。

    进程 i 从第 st[i] 段首开始活动，任务列表为 k[i] 个二元组 (ai,ti)，表示第 j 次任务要申请的资源编号与持续段数。同一进程的所有申请资源两两不同。进程处于“资源申请”或“任务运行”状态。

    申请成功的当段就进入任务运行，持续 ti 段；这段任务结束后下一段首申请下一项资源。在任务运行的每一段中，收益为该进程当时实际占有的资源种数；资源申请状态不产生收益。所有任务完成的当段末，进程停止并释放全部仍占有的资源。之前完成任务的资源不会自动释放，会继续占有直到全部任务结束或特殊行为发生。

    普通申请与冲突

    同一段首若多个处于申请状态的进程请求资源 x：若 x 已被占有，则都失败；若 x 待使用，则编号最小的进程成功并占有 x，其余失败。失败进程下一段首继续申请同一资源，且失败段中无收益。

    三种特殊进程

    普通进程记为 X，特殊进程 A/B/C 另有耐心值 w[i]。假设第 s 段首第一次申请当前资源 x，前 w[i] 次申请（第 s 至 s+w[i]-1 段首）全部失败，则：

    • A：在第 s+w[i]-1 段末释放仍占有的全部资源，继续申请 x，直到成功。以后不重新申请已经放弃的旧资源。下一任务再次失败时仍遵守 A 规则。

    • B：在第 s+w[i]-1 段首本次失败后，立即放弃 x 并进入当前任务，从该段中开始运行 ti 段；没有得到 x。

    • C：在第 s+w[i] 段首无视原归属，执行抢夺 x，并在该段进入任务运行。如果多个 C 同段抢夺同一资源，则编号最大的成功，其余抢夺失败但也进入任务运行、不会得到 x。若同段还存在其他任何类型的申请，则优先响应 C 抢夺，其他申请失败。

    被抢夺者可能是任意类型、可能正在运行或正在等待另一资源。失去资源只影响收益，不会打断或重启它的任务。特殊抢夺后的资源归属用于本段中收益计算。

    所有进程结束后系统终止。题面定义在第 10^100 段末仍未结束时强行终止，强行终止自身不改变已经产生的收益。

    输入格式

    第一行 n、m，随后 n 行依次描述进程。

    • 普通进程：X st k a1 t1 a2 t2 ... ak tk。

    • 特殊进程：A/B/C st w k a1 t1 ... ak tk，首字符实际为 A、B 或 C。

    输出格式

    共 n 行，第 i 行两个整数：总收益、从开始活动到停止活动持续的段数。若该进程未正常结束而是系统强行终止，持续段数输出 -1。

    范围与子任务

    • 前 40% 数据：没有特殊类型进程（全部 X）。

    • 另外 40% 数据：没有 C 类型进程（可有 X、A、B）。

    • 全部数据：1≤n≤10，1≤m≤40，1≤st[i]≤20，1≤w[i]≤20，1≤k[i]≤40，1≤ti≤20，1≤ai≤m，同一 i 下不同 j 的资源编号不同。

    样例与测试边界

    可见样例三个进程收益为 15、13、6，持续段数都为 10。样例 2 仅写“见题目目录下的 2.in 与 2.ans”，当前目录没有这两个文件，不能杜撰其内容或声称已测。

    边界包括永久死锁、同段释放不能立刻给其他申请者、A 与 B 触发相差一个阶段、C 比 B 晚一段、多个 C 取最大编号、正常申请取最小编号、抢夺待使用资源时仍优先、被抢夺的运行/等待进程、同段多资源交换、启动段 20、全部时长与耐心 20。

    样例 1

    输入：

    3 5
    X 1 3 1 3 3 4 4 3
    B 2 2 4 2 1 1 2 5 3 3 2
    C 3 3 2 1 2 4 2

    输出：

    15 10
    13 10
    6 10
